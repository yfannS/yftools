## 1. 项目概述

Markdown2HTML 是一个在线工具，用户可以在网页上输入 Markdown 文本，系统将其实时转化为美化后的 HTML 代码并展示。该工具面向需要快速将 Markdown 内容转换为美观 HTML 的开发者、内容创作者和文档编写者。

### 核心功能

- ✅ Markdown 实时编辑与预览
- ✅ Markdown → HTML 转换（后端 Goldmark 引擎）
- ✅ HTML 代码美化与格式化输出
- ✅ 一键复制 / 下载 HTML 文件
- ✅ 用户注册与登录（bcrypt 加密认证）
- ✅ 匿名访问（无需登录使用基础转换功能）
- ✅ 历史记录保存与查看（需登录）
- ✅ 多套预设主题切换
- ✅ 用户信息获取（接入企业认证）

### 架构特点

| 特点 | 说明 |
|------|------|
| Clean Architecture | 分层明确，handler → service → repository，通过接口解耦 |
| 依赖注入 | 所有依赖通过构造函数注入，无全局状态，便于测试 |
| 前后端分离 | 前端纯静态部署，后端提供 RESTful API |
| 跨域支持 | 后端通过 CORS 中间件支持跨域请求 |
| 模块化前端 | JS 按功能拆分为独立 ES Module |
| 可独立部署 | 前后端可分别部署在不同服务器/域名下 |
| 一体化部署 | 支持 Docker 构建，将前端静态文件打包进后端容器中 |

## 4. 后端技术说明

### 4.1 技术栈

| 组件 | 技术 | 用途 |
|------|------|------|
| 语言 | Go 1.22 | 后端开发语言 |
| Web 框架 | Gin 1.9.1 | HTTP 路由与中间件 |
| Markdown 解析 | Goldmark 1.7.4 | GFM 兼容的 Markdown → HTML 转换 |
| 密码加密 | golang.org/x/crypto/bcrypt | 用户密码 bcrypt 加密 |
| 数据库驱动 | go-sql-driver/mysql 1.8.1 | MySQL 连接 |
| 数据库 | MySQL 8.0+ | 历史记录与用户持久化存储 |

### 4.2 核心模块说明

#### `cmd/server/main.go` — 应用入口

- 加载配置（环境变量）并验证
- 初始化数据库连接
- **依赖注入**：依次初始化 repository → service → handler
- 注册全局中间件（CORS）
- 注册 API 路由分组 `/api`
- 提供静态文件服务 `/static`
- 启动 HTTP 服务（默认 `:8000`）

```go
// 依赖注入示例
userRepo := repository.NewUserRepository(db)
convRepo := repository.NewConversionRepository(db)
userSvc := service.NewUserService(userRepo)
convSvc := service.NewConversionService(convRepo)
themeSvc := service.NewThemeService()
h := handler.New(userSvc, convSvc, themeSvc)
```

#### `internal/handler/handler.go` — HTTP 处理器层

- **职责**：请求解析、参数校验、调用 service、构造响应
- **不包含业务逻辑**，业务逻辑全部委托给 service 层
- 路由对应表：

| 路由 | 处理器方法 | 说明 |
|------|-----------|------|
| `POST /api/convert` | `ConvertMarkdown` | Markdown → HTML 转换 |
| `POST /api/auth/register` | `Register` | 用户注册 |
| `POST /api/auth/login` | `Login` | 用户登录 |
| `GET /api/auth/profile` | `GetProfile` | 获取用户资料（需认证） |
| `GET /api/history` | `GetHistory` | 获取历史记录（需认证） |
| `POST /api/history` | `SaveHistory` | 保存历史记录（需认证） |
| `DELETE /api/history/:id` | `DeleteHistory` | 删除历史记录（需认证） |
| `GET /api/themes` | `GetThemes` | 获取主题列表 |

#### `internal/service/service.go` — 业务逻辑层

- **职责**：封装核心业务规则，通过接口与 repository 层交互
- 不依赖任何 HTTP 或框架细节，便于单元测试和复用
- 定义的服务接口：

```go
// UserService — 用户业务
Register(req model.RegisterRequest) error
Login(req model.LoginRequest) (string, error)
GetProfile(username string) (*model.UserAuth, error)

// ConversionService — 转换业务
Convert(markdown string) (rawHTML, formattedHTML string, err error)
SaveHistory(userID, userName, markdown, html, theme string) (int64, error)
GetHistory(userID string, page, pageSize int) (*model.HistoryResponse, error)
DeleteHistory(id int64, userID string) error

// ThemeService — 主题业务
GetThemes() []model.Theme
```

#### `internal/repository/repository.go` — 数据访问层

- **职责**：与数据库交互，封装所有 CRUD 操作
- 通过接口定义依赖，便于单元测试时 mock

```go
// UserRepository — 用户仓储
FindByUsername(username string) (*model.UserAuth, error)
Create(username, passwordHash string) (int64, error)

// ConversionRepository — 转换记录仓储
Create(userID, userName, markdown, html, theme string) (int64, error)
ListByUserID(userID string, page, pageSize int) ([]model.Conversion, int, error)
DeleteByIDAndUserID(id int64, userID string) (bool, error)
```

#### `internal/middleware/middleware.go` — 中间件

- `CORS()` — 全局跨域中间件
- `AuthMiddleware()` — 认证中间件，从 `Authorization: Bearer <token>` 解析用户名，注入 gin 上下文
- `GetUsername(c)` — 从上下文中安全获取用户名

#### `internal/config/config.go` — 配置管理

- 从环境变量加载配置（遵循 12-Factor App）
- 验证必要的数据库连接信息
- 创建数据库连接并设置连接池参数
- **自动建表**：启动时自动创建 `user_auth` 和 `conversions` 表

#### `pkg/converter/converter.go` — Markdown 转换引擎

- **独立于业务层的共享工具包**
- 基于 Goldmark 实现 Markdown → HTML 转换
- 包含 `FormatHTML()` 方法对输出进行格式化美化（缩进对齐）
- 可被独立使用和测试

## 6. API 接口文档

### 基础信息

- **Base URL**: `http://localhost:8000/api`（开发环境）
- **认证方式**: 
  - 公开接口（转换、主题）：无需认证
  - 需登录接口（注册/登录除外）：请求头携带 `Authorization: Bearer <token>`
  - 兼容方式：请求头携带 `X-User-ID` 和 `X-User-Name`
- **响应格式**: 统一 JSON

---

### 6.1 用户注册

#### POST /api/auth/register

注册新用户，用户名和密码加密存储。

**请求体:**

```json
{
  "username": "myuser",
  "password": "mypassword"
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `username` | string | 是 | 用户名，3-32 字符 |
| `password` | string | 是 | 密码，至少 6 位 |

**响应:**

```json
{
  "success": true,
  "user": "myuser",
  "message": "注册成功，请登录"
}
```

**错误响应:**

```json
{
  "success": false,
  "message": "用户名已存在"
}
```

---

### 6.2 用户登录

#### POST /api/auth/login

用户登录，验证通过后返回 token。

**请求体:**

```json
{
  "username": "myuser",
  "password": "mypassword"
}
```

**响应:**

```json
{
  "success": true,
  "token": "m2h_myuser",
  "user": "myuser",
  "message": "登录成功"
}
```

**错误响应:**

```json
{
  "success": false,
  "message": "用户名或密码错误"
}
```

---

## 7. 数据库设计

### 7.1 数据库信息

| 项目 | 值 |
|------|-----|
| 字符集 | `utf8mb4` |
| 存储引擎 | `InnoDB` |

### 7.2 表结构

#### user_auth - 用户注册登录表

```sql
CREATE TABLE user_auth (
  id            BIGINT AUTO_INCREMENT PRIMARY KEY,
  username      VARCHAR(128)  NOT NULL UNIQUE COMMENT '用户名',
  password_hash VARCHAR(255)  NOT NULL COMMENT 'bcrypt 加密密码',
  created_at    DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_username (username)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户注册登录表';
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BIGINT | 主键，自增 |
| `username` | VARCHAR(128) | 用户名，唯一 |
| `password_hash` | VARCHAR(255) | bcrypt 加密后的密码 |
| `created_at` | DATETIME | 注册时间 |

#### conversions - 转换历史记录表

```sql
CREATE TABLE conversions (
  id         BIGINT AUTO_INCREMENT PRIMARY KEY,
  user_id    VARCHAR(128)  NOT NULL COMMENT '用户英文账号',
  user_name  VARCHAR(128)  DEFAULT '' COMMENT '用户中文名',
  markdown   TEXT          NOT NULL COMMENT 'Markdown 原文',
  html       TEXT          COMMENT '转换后的 HTML',
  theme      VARCHAR(64)   DEFAULT 'default' COMMENT '使用的主题',
  created_at DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_user_id (user_id),
  INDEX idx_created_at (created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='Markdown 转换历史记录';
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BIGINT | 主键，自增 |
| `user_id` | VARCHAR(128) | 用户标识，用于数据隔离 |
| `user_name` | VARCHAR(128) | 用户显示名称 |
| `markdown` | TEXT | 原始 Markdown 内容 |
| `html` | TEXT | 转换后的 HTML（可空） |
| `theme` | VARCHAR(64) | 主题 ID |
| `created_at` | DATETIME | 创建时间 |

**前端部署:**

将 `frontend/` 目录下的文件部署到任意静态文件服务器：

**Nginx 反向代理配置（推荐）:**

```nginx
server {
    listen 80;
    server_name your-domain.com;

    # 前端静态文件
    location / {
        root /path/to/frontend;
        index index.html;
        try_files $uri $uri/ =404;
    }

    # 后端 API 反向代理
    location /api/ {
        proxy_pass http://localhost:8000/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

- [x] 新增 `internal/config/` — 统一配置管理与数据库初始化，支持自动建表

- [x] 新增 `internal/service/` — 业务逻辑层，封装核心业务规则
- [x] 新增 `pkg/converter/` — 共享工具包，Markdown 转换引擎独立于业务层

**设计原则：**
- 接口驱动开发（IDF）：所有 service 和 repository 均定义接口
- 依赖注入（DI）：无全局状态，依赖通过构造函数注入
- 关注点分离：handler 不处理业务逻辑、service 不依赖 HTTP 细节、repository 只负责数据访问
