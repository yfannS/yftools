## 3. 推荐方案

### 3.1 新前端目录命名

推荐新目录：

- **`D:\learn\md2html\webapp`**

理由：

- 与现有 `frontend` 区分明确
- 避免 `frontend-v2` 这类临时命名长期固化
- 后续若存在管理端/官网端，也更容易继续扩展

### 3.2 推荐技术栈

**单一推荐：Vue 3 + TypeScript + Vite + Pinia + Vue Router**

补充库：

- Markdown：`marked`
- 安全清洗：`DOMPurify`
- 高亮：`highlight.js`
- 图表：`mermaid`
- 数学公式：`katex`
- 样式：`Tailwind CSS` 或 Tailwind + 少量 scoped CSS
- HTTP：`fetch` 封装或 `axios` 二选一，优先延续现有 fetch 风格

### 3.3 为什么推荐 Vue 而不是 React

当前纯前端版本的大量能力属于“**Markdown 渲染后再做 DOM 后处理**”模式，例如：

- Mermaid 渲染后挂下载按钮
- 代码块高亮后补复制按钮
- 图片/流程图 lightbox
- 导出 HTML 时重新拼装 DOM

这类场景在 Vue 中用 `ref + nextTick + composable` 迁移更顺手，改造成本会低于 React 的受控渲染 + effect 编排。

## 4. 架构边界划分

### 4.1 前端负责

- 编辑器 UI 与交互体验
- Markdown 本地解析与实时预览
- Mermaid / KaTeX / highlight 的前端渲染
- 导出 HTML
- 代码复制、图片/流程图放大、拖拽分栏、查找替换
- 本地草稿、最近状态缓存
- 登录态展示、历史页/分组页 UI

### 4.2 后端负责

- 用户认证
- 文件上传
- 历史记录持久化
- 分组管理
- 服务端 Markdown 转换接口（如继续保留）
- 主题配置接口

### 4.3 兼容层负责

新前端需要一层 `services/compat` 或 `services/fallback`：

- 后端可用：调用 `/api/*`
- 后端不可用：继续保留本地降级能力
- 登录用户：在线功能全开
- 未登录用户：仍可本地编辑、预览、导出

一句话总结：**新版本不是纯在线工具，而是“在线增强 + 离线可用”的前后端分离应用。**

## 7. 核心设计原则

### 7.1 渲染主链路仍以本地为主

推荐默认策略：

- 编辑态实时预览：**前端本地渲染优先**
- 后端 `/api/convert`：作为兼容能力或可切换能力

原因：

- 当前纯前端版本的体验最强项就是“本地即时反馈”
- Mermaid、KaTeX、导出 HTML、代码块交互都强依赖前端后处理
- 如果把预览主链路切回服务端，会重新引入交互能力不一致的问题

### 7.2 在线能力采用“增强而不是替代”

即：

- 没登录：仍然能写、看、导出
- 登录后：额外获得上传、历史、分组、主题、云端记录

### 7.3 导出链路单独模块化

当前 `buildFullHTML()` 逻辑很重，迁移后必须拆成：

- HTML 模板构造
- 主题变量注入
- Mermaid 导出脚本注入
- Lightbox 注入
- 代码复制脚本注入
- 外部 CDN 依赖注入

否则后续维护成本会快速失控。

## 9. 风险点与规避策略

### 风险 1：Markdown 渲染后处理链路太重

问题：Mermaid / KaTeX / 高亮 / 复制按钮 / lightbox 都依赖 DOM 后处理。
规避：统一收口到 `services/markdown/postprocess.ts`，由单一渲染管线调度。

### 风险 2：导出 HTML 能力迁移最容易丢功能

问题：当前导出逻辑已积累很多细节坑（script 转义、Mermaid 客户端渲染、复制按钮注入等）。
规避：导出逻辑单独模块化，并建立导出用例清单逐项回归。

### 风险 3：服务端转换与前端本地渲染不一致

问题：服务端 HTML 结果可能不具备当前前端交互能力。
规避：编辑态仍以前端渲染为主；服务端转换仅用于兼容或特殊场景。

### 风险 4：直接照搬参考 frontend 会倒退体验

问题：参考 frontend 的交互能力明显弱于当前纯前端版。
规避：以 `md2html_pureFrontend` 为主干，以 `frontend` 为在线能力补丁源，而不是反过来。

### 风险 5：新旧 token / storage 命名冲突

规避：统一给新前端 localStorage / IndexedDB key 加命名空间前缀，例如 `m2h_webapp_*`。
