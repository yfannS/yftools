# md2html 后端历史记录功能完善 — 技术方案

> 版本：v2.0 | 日期：2026-06-06

---

## 一、需求概述

| # | 需求 | 说明 |
|---|------|------|
| 1 | 前端每次 MD 转换后自动保存原文 | 只传 `markdown`，`html` 改为可选（前端本地渲染） |
| 2 | 历史列表轻量返回 | 只返回 `id, title, char_count, theme, created_at`，不查 MEDIUMTEXT 大字段 |
| 3 | 点击记录查看详情 | 新增 `GET /history/:id` 接口，返回完整 `markdown` |
| 4 | 自动提取文档标题 | 从 markdown 中按 H1→H2→H3→…→首行 顺序提取标题，作为列表显示名 |
| 5 | UPSERT 防重复 | 同一用户短时间内相同标题的记录视为同一次编辑，更新而非新增 |

## 二、数据库设计

### 2.1 `md2html_conversions` 表（完整 DDL）

```sql
CREATE TABLE IF NOT EXISTS md2html_conversions (
    id         BIGINT AUTO_INCREMENT PRIMARY KEY  COMMENT '文档唯一 ID',
    user_id    BIGINT       NOT NULL              COMMENT '用户 ID',
    title      VARCHAR(255) NOT NULL DEFAULT ''   COMMENT '文档标题（从 Markdown 标题提取）',
    markdown   MEDIUMTEXT   NOT NULL              COMMENT 'Markdown 原文',
    html       MEDIUMTEXT   NULL                  COMMENT '转换后的 HTML（可选，前端本地渲染时不存）',
    char_count INT          NOT NULL DEFAULT 0    COMMENT 'Markdown 字符数',
    theme      VARCHAR(64)  DEFAULT 'default'    COMMENT '使用的主题 ID',
    created_at DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    is_delete  TINYINT     NOT NULL DEFAULT 0    COMMENT '软删除标记：0=未删除，1=已删除',
    updated_at DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

    INDEX idx_user_id       (user_id),
    INDEX idx_user_delete   (user_id, is_delete),
    INDEX idx_user_updated  (user_id, updated_at DESC),
    CONSTRAINT fk_md2html_user FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='md2html 转换历史记录';
```

### 2.2 字段变更对比

| 字段 | 旧设计 | 新设计 | 变更原因 |
|------|--------|--------|----------|
| `title` | 无 | `VARCHAR(255) NOT NULL DEFAULT ''` | **新增**：从 markdown 标题行自动提取，替代 preview，更直观 |
| `preview` | 旧方案中 `VARCHAR(64)` | **删除** | 用 title 替代，标题比截取前 30 字符更有语义 |
| `html` | `NOT NULL` | `NULL` | 前端本地渲染时无需存储 html |
| `char_count` | 无 | `INT NOT NULL DEFAULT 0` | **新增**：列表页展示文档字数 |
| `updated_at` | 无 | `DATETIME` | **新增**：UPSERT 更新时间戳，列表按此排序 |
| `is_delete` | 无 | `TINYINT NOT NULL DEFAULT 0` | **新增**：软删除标记，0=未删除，1=已删除 |

### 2.3 索引设计

| 索引名 | 列 | 用途 |
|--------|-----|------|
| `PRIMARY` | `id` | 文档唯一 ID，详情查询 |
| `idx_user_id` | `user_id` | 按用户查询历史记录 |
| `idx_user_updated` | `(user_id, updated_at DESC)` | **复合索引**：列表按用户+更新时间倒序分页，覆盖查询 |
| `idx_user_delete` | `(user_id, is_delete)` | **复合索引**：软删除过滤，加速 `WHERE user_id = ? AND is_delete = 0` |

## 三、标题提取规则

### 3.1 提取优先级

```
1. 第一个 # 标题（H1）
2. 若无 H1 → 第一个 ## 标题（H2）
3. 若无 H2 → 第一个 ### 标题（H3）
4. ...
5. 若无任何标题 → 取第一个非空行的前 60 字符
6. 若整篇为空 → 返回 "未命名文档"
```

### 3.2 实现逻辑（Go 伪代码）

```go
func ExtractTitle(markdown string) string {
    lines := strings.Split(markdown, "\n")
    // 优先级 1-6：匹配 # ~ ###### 标题
    for level := 1; level <= 6; level++ {
        prefix := strings.Repeat("#", level) + " "
        for _, line := range lines {
            trimmed := strings.TrimSpace(line)
            if strings.HasPrefix(trimmed, prefix) {
                title := strings.TrimSpace(strings.TrimPrefix(trimmed, prefix))
                if title != "" {
                    // 截断到 200 字符
                    if len([]rune(title)) > 200 {
                        return string([]rune(title)[:200])
                    }
                    return title
                }
            }
        }
    }
    // 优先级 7：第一个非空行
    for _, line := range lines {
        trimmed := strings.TrimSpace(line)
        if trimmed != "" {
            if len([]rune(trimmed)) > 60 {
                return string([]rune(trimmed)[:60]) + "..."
            }
            return trimmed
        }
    }
    return "未命名文档"
}
```

### 3.3 标题提取时机

- **后端**：`Save` 接口收到 markdown 后，调用 `ExtractTitle()` 自动提取，**前端无需传 title**
- 如果未来需要用户手动修改标题，可以在 `SaveHistoryRequest` 中加可选的 `title` 字段覆盖自动提取

## 五、Repository 层设计

### 5.1 接口定义

```go
type HistoryRepository interface {
    // 保存记录（INSERT 或 UPSERT），返回记录 ID
    Save(userID int64, title, markdown, html string, charCount int, theme string) (int64, error)

    // 列表查询（轻量，不含 markdown/html）
    ListByUserID(userID int64, page, pageSize int) ([]model.HistoryListItem, int64, error)

    // 详情查询（含完整 markdown）
    FindByIDAndUserID(id, userID int64) (*model.HistoryDetail, error)

    // 软删除（将 is_delete 设为 1）
    DeleteByIDAndUserID(id, userID int64) error

    // 查找用户最近一条相同标题的记录（UPSERT 判断）
    FindRecentByUserIDAndTitle(userID int64, title string) (*model.Conversion, error)
}
```

### 5.2 Save — UPSERT 策略

```
入参：userID, title, markdown, html, charCount, theme

1. 查询 FindRecentByUserIDAndTitle(userID, title)
2. 如果找到 且 updated_at 在 5 分钟内：
   → UPDATE 该记录：markdown, html, char_count, updated_at = NOW()
   → 返回该记录 id
3. 否则：
   → INSERT 新记录
   → 返回新 id
```

**防重复场景**：用户持续编辑同一篇文档（标题不变），5 分钟窗口内只保留一条记录，避免产生大量碎片。

### 5.3 ListByUserID — 轻量查询

```sql
SELECT id, title, char_count, theme, created_at, updated_at
FROM md2html_conversions
WHERE user_id = ? AND is_delete = 0
ORDER BY updated_at DESC
LIMIT ? OFFSET ?
```

**关键**：不 SELECT `markdown` 和 `html` 列，避免 InnoDB 读取 MEDIUMTEXT 大字段。`is_delete = 0` 过滤已软删除的记录。

### 5.4 FindByIDAndUserID — 详情查询

```sql
SELECT id, title, markdown, html, char_count, theme, created_at, updated_at
FROM md2html_conversions
WHERE id = ? AND user_id = ? AND is_delete = 0
```

**安全**：必须带 `user_id` 条件，防止越权访问他人记录。`is_delete = 0` 确保已删除的记录不可访问。

### 5.5 FindRecentByUserIDAndTitle — UPSERT 辅助查询

```sql
SELECT id, title, updated_at
FROM md2html_conversions
WHERE user_id = ? AND title = ? AND is_delete = 0
ORDER BY updated_at DESC
LIMIT 1
```

**注意**：只匹配未删除的记录，避免 UPSERT 到已软删除的记录上。

## 十、数据库迁移方案

### 10.1 增量迁移 SQL

表已存在，需 ALTER TABLE：

```sql
-- 1. html 列改为允许 NULL
ALTER TABLE md2html_conversions MODIFY COLUMN html MEDIUMTEXT NULL
    COMMENT '转换后的 HTML（可选，前端本地渲染时不存）';

-- 2. 新增 title 列
ALTER TABLE md2html_conversions ADD COLUMN title VARCHAR(255) NOT NULL DEFAULT ''
    COMMENT '文档标题（从 Markdown 标题提取）' AFTER user_id;

-- 3. 新增 char_count 列
ALTER TABLE md2html_conversions ADD COLUMN char_count INT NOT NULL DEFAULT 0
    COMMENT 'Markdown 字符数' AFTER html;

-- 4. 新增 updated_at 列
ALTER TABLE md2html_conversions ADD COLUMN updated_at DATETIME NOT NULL
    DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP AFTER created_at;

-- 5. 回填现有数据的 title（从 markdown 提取标题）
-- 注意：此步骤需在应用层执行（Go 代码遍历），因为 SQL 无法实现标题提取逻辑
-- 简易回填：取 markdown 第一个 # 标题行，若没有则取首行前 60 字符
UPDATE md2html_conversions SET title =
    CASE
        WHEN LOCATE('# ', markdown) > 0 THEN
            TRIM(SUBSTRING(
                SUBSTRING(markdown, LOCATE('# ', markdown)),
                3,
                LOCATE(CHAR(10), SUBSTRING(markdown, LOCATE('# ', markdown))) - 3
            ))
        ELSE LEFT(TRIM(markdown), 60)
    END
WHERE title = '';

-- 6. 回填 char_count
UPDATE md2html_conversions SET char_count = CHAR_LENGTH(markdown) WHERE char_count = 0;

-- 7. 回填 updated_at（用 created_at 初始化）
UPDATE md2html_conversions SET updated_at = created_at WHERE updated_at = created_at AND updated_at < NOW() - INTERVAL 1 DAY;

-- 8. 新增复合索引
ALTER TABLE md2html_conversions ADD INDEX idx_user_updated (user_id, updated_at DESC);

-- 9. 新增 is_delete 列
ALTER TABLE md2html_conversions ADD COLUMN is_delete TINYINT NOT NULL DEFAULT 0
    COMMENT '软删除标记：0=未删除，1=已删除' AFTER theme;

-- 10. 新增软删除过滤索引
ALTER TABLE md2html_conversions ADD INDEX idx_user_delete (user_id, is_delete);
```

### 10.2 幂等性保证

在 `RunMigrations` 中采用以下策略：

```
1. SHOW COLUMNS FROM md2html_conversions 检查列是否存在
2. 列不存在 → 执行 ALTER TABLE ADD COLUMN
3. 列已存在 → 跳过
4. SHOW INDEX FROM md2html_conversions 检查索引是否存在
5. 索引不存在 → 执行 ALTER TABLE ADD INDEX
6. 索引已存在 → 跳过
```
